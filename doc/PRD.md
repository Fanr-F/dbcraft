## 1. 产品概述

### 1.1 背景

开发人员在日常工作中需要频繁访问 SQLite、MySQL 系（MySQL / Percona / MariaDB）、MSSQL 数据库（本地 SQLite 文件、测试/预发 MySQL 系、Windows 环境下的 MSSQL 等），当前痛点：

1. 现有工具分裂：SSMS 只支持 MSSQL，SQLite 工具功能简陋，跨库工具（DataGrip/DBeaver）要么收费昂贵、要么体积庞大、要么学习成本高。
2. 重复输入 SQL：缺乏开箱即用的、方言感知的语句补全体验。
3. 查过即忘：执行过的 SQL 没有沉淀，下周想复用同一条查询时只能重写。
4. 改表靠手写：建表、改列、加索引等 DDL 操作需要手写并记忆三方言的语法差异，容易出错。

### 1.2 产品定位

面向开发人员的、支持 **SQLite / MySQL / Percona / MariaDB / MSSQL** 的轻量级桌面数据库客户端，强调：

- **快**：秒级启动、低内存占用；
- **全**：覆盖「连接 → 编写 → 执行 → 沉淀 → 改库结构 → 改数据」完整闭环；
- **稳**：高危操作可预览、可确认、可回滚；
- **轻**：单一安装包，零配置开箱即用。

> **边界原则**：DBCraft 不模拟、不修复数据库自身行为，也不处理历史遗留 schema/数据问题；版本与方言差异按数据库原生行为透传，高风险场景提示改用 SQL/CLI。

### 1.3 目标用户

| 用户画像 | 描述 | 典型诉求 |
|---|---|---|
| 后端开发工程师 | 日常操作 MySQL 系（MySQL/Percona/MariaDB）/MSSQL 测试库，偶尔查本地 SQLite | 快速执行 SQL、复用历史查询、改表结构 |
| 全栈/客户端开发 | 本地 SQLite 为主，联调 MySQL 系/MSSQL | 查看和修改本地 SQLite 文件 |
| DBA / 运维（次要） | 偶尔巡检、加索引 | 需要 DDL 预览和审计，不要求完整运维套件 |
| 测试工程师（次要） | 构造测试数据 | 表数据快速增删改 |

### 1.4 非目标用户（Out of Scope for v1）

- 需要多人协作、权限管控、审计报表的团队级 DBA 平台；
- 需要 HTAP/分析型场景（可视化 BI）;
- Oracle / PostgreSQL 等其他数据库（v1 不支持，架构上预留扩展可能）。

### 1.5 与竞品的差异化

| 竞品 | 优势 | 不足（DBCraft 的机会） |
|---|---|---|
| DataGrip | 补全强、跨库 | 付费、重、订阅 |
| DBeaver | 免费、跨库 | 体积大、启动慢、UI 复杂 |
| Navicat | UI 成熟 | 付费、闭源 |
| SSMS | MSSQL 原生体验 | 仅 MSSQL、Windows、庞大 |
| TablePlus | 轻量优雅 | 收费、闭源模式 |
| SQLiteStudio | SQLite 免费 | 单一数据库、UI 陈旧 |

**DBCraft 的定位**：免费/开源（**MIT License**）、轻量、SQLite / MySQL 系 / MSSQL 统一体验、历史查询与 DDL 效率优先。

- SSH 隧道、证书级 SSL/TLS 配置（MVP 仅提供基础加密开关，见 4.1.2）；
- 历史查询云同步（需用户确认）、工作区/项目（多连接快速切换）；
- 查询执行计划展示与优化建议；
- 参数化查询（命名参数/占位符）与查询收藏夹；
- SQL Server Agent 其他对象（Operators / Alerts / Proxies）、Job 的 UI 创建/编辑向导（v0.13 决策：启动/停止/启用/禁用按钮已纳入 v1.0；配置编辑仍统一走「生成脚本 → 编辑器执行」，见 MOD-08）；

- 数据同步、数据库迁移（schema diff 对比同步）；

- MSX/TSX 多服务器作业集中管理（需要专项研究，v1.0 检测到时只读标注「[多服务器]」）。

## 3. 全局交互与信息架构

### 3.1 主界面布局

```
┌────────────────────────────────────────────────────────────┐
│ 顶部工具栏：连接选择框 / 新建连接 / 历史 / 设置 / 主题        │
├──────────┬─────────────────────────────┬───────────────────┤
│  对象树   │   SQL 编辑器（多标签页）      │  右侧：属性/DDL    │
│  （连接   │   ・标签页 = 一个查询上下文   │  预览（可折叠）    │
│  → 库 →  │   ・底部状态栏：方言/耗时/行数 │                   │
│  表/视图）│                             │                   │
│          ├─────────────────────────────┤                   │
│  可折叠   │   结果集网格 / 消息面板       │                   │
│          │   ・多结果集页签 / 错误提示    │                   │
└──────────┴─────────────────────────────┴───────────────────┘
│ 状态栏：连接状态 / 当前库 / 事务状态 / 数据库时区              │
└────────────────────────────────────────────────────────────┘
```

> MSSQL 连接的对象树额外包含「SQL Server Agent → 作业」节点（见 MOD-08）；SQLite / MySQL 系无此节点。
>
> 主区域页签类型统一为：SQL 查询、表数据、DDL 预览/设计视图、作业列表、作业详情。页签可混合排列、可多开；同一对象重复打开时聚焦已有页签（作业列表允许按连接多开）。
>
> 状态栏「事务状态」分别标识当前 SQL 标签的显式事务（`BEGIN`/`COMMIT`）与网格未提交更改，两者互不影响（见 4.5.3 会话模型）。
>
> 顶部连接选择框与对象树选中连接保持同步；切换连接不关闭现有 SQL 标签，仅影响新建标签的默认连接。
>
> 右侧「属性/DDL 预览」用于常驻查看对象信息与生成脚本；执行确认仍走 4.4.5 的模态预览弹窗。

### 3.2 通用交互规范

- 快捷键（可自定义，默认对齐 VS Code；与 Monaco/RevoGrid 内置键冲突时以本表为准并在设置中可改）：
  - `Ctrl/Cmd + Enter`：执行当前语句（或选中部分）
  - `Ctrl/Cmd + Space`：触发补全
  - `Shift + Alt + F`：格式化 SQL（与 VS Code 一致；`Ctrl/Cmd + Shift + F` 保留给全局搜索）
  - `Ctrl/Cmd + Shift + X`：清空结果集
  - `Ctrl/Cmd + E`：查看查询历史
  - `F2`：对象树/设计视图中重命名；网格中 `F2` 进入单元格编辑（两者不共存于同一焦点区域）
  - `Delete`：网格删除选中行（需确认）
- 深/浅色主题跟随系统，可手动切换。
- 所有危险操作（DROP、TRUNCATE、删除列、批量删除/更新行）必须二次确认；DDL 与批量 DML 均展示将执行的 SQL（见 MOD-04、MOD-05）。
- 所有 UI 生成的 DDL 必须先进入「SQL 预览」，用户确认后方可执行（见 MOD-04）。
- 连接可标记「生产/只读」；生产连接默认拦截 DROP/TRUNCATE 与无 WHERE 的 UPDATE/DELETE，需二次确认（编辑器手写语句同样生效）。

### 3.3 多库方言差异处理原则（SQLite / MySQL 系 / MSSQL）

| 差异点 | SQLite | MySQL 系（MySQL / Percona / MariaDB） | MSSQL | 产品策略 |
|---|---|---|---|---|
| 默认端口 | —（文件） | 3306 | 1433 | 连接表单按类型切换字段 |
| 发行版 | — | MySQL / Percona / MariaDB 独立类型 | — | 连接创建、认证、驱动分别处理 |
| 自增列 | `INTEGER PRIMARY KEY AUTOINCREMENT` | `AUTO_INCREMENT` | `IDENTITY(1,1)` | 类型选择器内置三套模板 |
| 分页 | `LIMIT ? OFFSET ?` | `LIMIT ? OFFSET ?` | `TOP` / `OFFSET ... FETCH` | 对用户透明，UI 统一页码分页 |
| 字符串 | `'` 单引号 | `'` 单引号 | `N'`（Unicode）/ `'` | 编辑器与导出按方言处理 |
| 认证 | 无（v1.0 不支持加密文件） | MySQL/Percona：`caching_sha2_password`、`mysql_native_password`、`sha256_password`；MariaDB：`mysql_native_password`、`ed25519`、`unix_socket` | SQL 认证（v1.0）；Windows 集成认证 v1.x | 连接表单按发行版切换 |
| 批分隔符 | `;` | `;` | `GO` | 执行器识别 `GO`，结果集分批返回 |
| 注释 | `--` `/* */` | `--` `#` `/* */` | `--` `/* */` | 补全与高亮按方言 |

### 3.4 版本与能力基线

| 数据库 | v1.0 基线 | 说明 |
|---|---|---|
| SQLite | 3.35+（由驱动内置） | 3.35 起支持 `DROP COLUMN`，3.25 起支持 `RENAME COLUMN`；低于基线时降级为重建表并提示 |
| MySQL | 5.7 / 8.0 / 8.4 | 独立连接类型；按服务器版本过滤补全与 DDL 能力（CTE/窗口函数/JSON 等） |
| Percona | 8.0 / 8.4 | 独立连接类型；沿用 MySQL 方言与认证；版本差异按数据库原生行为处理 |
| MariaDB | 10.3+ | 独立连接类型；认证插件、类型/DDL 差异按数据库原生行为处理，不做额外版本兼容层 |
| MSSQL | 2016 / 2017 / 2019 / 2022 | 以 `SERVERPROPERTY('ProductMajorVersion')` 判定；Azure SQL 未认证，Agent 节点不显示 |

- 字符集：MySQL 系默认 `utf8mb4`；会话字符集可配置。时区不做应用层转换：显示/导出以数据库返回值为准，有时区类型保留偏移，无时区类型不补时区。
- 会话 SET：MSSQL 执行 DDL 前统一设置 `ANSI_NULLS ON`、`QUOTED_IDENTIFIER ON`；SQLite 连接默认 `PRAGMA foreign_keys=ON`、`busy_timeout=5000`。
- 分句规则：`;`（SQLite/MySQL 系）与 `GO`（MSSQL，必须独占一行、忽略大小写）为批分隔符；字符串、注释、MySQL 系 `DELIMITER` 内的分隔符不切分。

### MOD-01 连接管理（P0）

#### 4.1.1 功能描述

用户可创建、编辑、删除、分组、测试连接，并从本地文件系统拖入或选择 SQLite 文件。

#### 4.1.2 连接配置字段

| 字段 | SQLite | MySQL 系（MySQL / Percona / MariaDB） | MSSQL | 说明 |
|---|---|---|---|---|
| 数据库类型 | SQLite | MySQL / Percona / MariaDB（单选） | MSSQL | 连接创建第一步选择发行版 |
| 显示名称 | ✓ | ✓ | ✓ | 默认建议 `类型-主机:库名` |
| 环境标签 | ✓ | ✓ | ✓ | 开发/测试/生产；生产连接默认启用危险语句拦截（见 3.2） |
| 分组 | ✓ | ✓ | ✓ | 支持多级分组（如「项目A/测试环境」） |
| 数据库文件路径 | ✓ | — | — | 支持浏览选择；打开即测试 |
| 主机/端口 | — | ✓(3306) | ✓(1433；可填 `host\instance` 或 `host:port`，二者互斥) | 填写实例名时忽略端口，走 SQL Browser 解析 |
| 数据库名 | — | ✓(可为空=默认库) | ✓ | |
| 用户名/密码 | —（v1.0 不支持加密 SQLite 文件） | ✓ | ✓（v1.0 仅 SQL 认证） | 密码本地加密存储（见 5.3）；Windows 集成认证列入 v1.x |
| 认证插件 | — | MySQL/Percona：`caching_sha2_password` / `mysql_native_password` / `sha256_password`；MariaDB：`mysql_native_password` / `ed25519` / `unix_socket` | SQL 认证 | 按发行版展示可用插件；测试连接时校验 |
| 连接超时/查询超时/测试超时 | 可选 | ✓ | ✓ | 单位秒；连接默认 10、查询默认 30、测试连接 5 |
| SSL/TLS | — | ✓（MVP 基础开关：启用/禁用、跳过证书校验） | ✓（MVP 基础开关：`encrypt` / `trustServerCertificate`） | 详细证书/CA/客户端证书配置列入 v1.x |
| 字符集/时区 | — | ✓（字符集默认 `utf8mb4`；时区不转换，以数据库返回值为准） | —（以服务器时区与列类型为准） | 高级项，默认折叠 |

#### 4.1.3 功能需求

- 新建连接：第一步选择 SQLite / MySQL / Percona / MariaDB / MSSQL；MySQL 系按发行版展示认证插件、默认端口与连接参数，保存前「测试连接」，失败给出可读错误（如端口不通、认证插件不匹配、认证失败、文件不存在/无读写权限）。
- 连接搜索：对象树顶部搜索框，按名称/主机/库名过滤连接；支持按分组折叠后仍可搜索。
- 对象搜索：连接到库后，可按表/视图名过滤当前库对象（大小写不敏感）；系统对象默认隐藏，可开关「显示系统对象」。
- 连接右键：编辑、复制、删除、断开、新建查询、查看 DDL（库级，仅生成当前库对象的结构脚本）。
- 连接健康状态：图标显示 已连接/连接中/失败（悬停显示失败原因）。
- 分组管理：支持多级分组的新建/重命名/删除/拖拽移动；删除分组时连接移至「未分组」，不删除连接。
- 复制连接：复制除密码外的配置，保存时需重新输入密码。
- 删除连接：二次确认；删除本地凭据与 schema 缓存，历史记录保留并标记「连接已删除」（见 MOD-03）。
- 连接导入/导出（P1）：JSON 格式，导出**永不包含密码**；导入时密码需重新输入。
- 最近使用的连接排序靠前。

#### 4.1.4 异常处理

- SQLite 文件被占用（WAL 模式）：以只读方式打开并明确提示「当前为只读，写入操作已禁用」；同时设置 `busy_timeout`，超时后给出可读提示。
- MSSQL 仅有实例名无端口：走 SQL Browser（UDP 1434），超时给出「实例不可用，请改用端口连接」。
- MySQL / Percona：默认 `caching_sha2_password`；非 TLS 连接需启用 `allowPublicKeyRetrieval` 或配置 SSL，失败时按此提示，不强制降级 `mysql_native_password`。
- MariaDB：认证插件与 MySQL 不同，支持 `mysql_native_password`、`ed25519`、`unix_socket` 等；`ed25519` 由 MariaDB 驱动处理，不与非 MariaDB 共用同一认证实现。插件不匹配时提示具体插件名与可用选项。
- Percona 按 MySQL 认证路径处理；连接测试读取 `VERSION()`/`@@version_comment` 识别发行版，仅用于展示与诊断，不做版本兼容层。
- MSSQL 加密：云实例/新版实例常要求加密；连接表单提供 `encrypt` 与 `trustServerCertificate`，证书不受信任时给出明确提示而非裸驱动错误。
- 断线自动检测：执行失败且错误码为连接丢失时，状态栏置为断开，提供「重连」按钮；重连后清理失效会话，未提交的网格更改保留在本地并提示重新提交。

#### 4.1.5 验收标准（节选）

- AC: Given 未配置任何连接，When 点击「新建连接」选择 SQLite 并选择一个有效 `.db` 文件，Then 测试通过并可浏览表列表。
- AC: Given 一个 MSSQL 连接配置错误（密码错误），When 测试连接，Then 在测试超时（5 秒）内返回「认证失败」提示且不保存为可用连接。
- AC: Given 连接配置列表超过 20 个，When 输入搜索关键词「pay」，Then 仅显示名称/主机/库名匹配的连接；分组内连接同样命中。
- AC: Given MySQL 连接启用 SSL 但证书不受信任，When 测试连接，Then 提示证书错误并给出「信任该证书/关闭加密」的明确选项。
- AC: Given 新建连接选择 Percona，When 使用 `caching_sha2_password` 账号测试，Then 连接成功且连接列表显示 Percona 发行版。
- AC: Given 新建连接选择 MariaDB，When 使用 `ed25519` 账号测试，Then 由 MariaDB 驱动完成认证并连接成功；使用不支持的认证插件时，错误文案包含插件名与可用选项。
- AC: Given SQLite 文件被其他进程占用，When 打开连接，Then 以只读模式打开并显示只读横幅，写操作按钮禁用。

### MOD-02 SQL 编辑器与语句补全（P0）

#### 4.2.1 功能描述

提供多标签 SQL 编辑器，核心能力为**上下文感知的补全**，以及格式化、执行、结果展示。

#### 4.2.2 补全范围与规则

| 补全类别 | 内容 | 触发时机/上下文 |
|---|---|---|
| 关键字 | SELECT/INSERT/UPDATE/DELETE/JOIN/WHERE/GROUP BY/ORDER BY/LIMIT/TOP/UNION/WITH… | 任意位置，大小写跟随当前风格 |
| 函数（按方言） | MySQL 系: `NOW()` `IFNULL()` `GROUP_CONCAT()`…；MSSQL: `GETDATE()` `ISNULL()` `LEN()`…；SQLite: 通用 + `strftime()` 等 | 输入标识符前缀时 |
| 库/Schema | 当前连接下可见的 database/schema 列表 | `库名.` 之后 / FROM 之后 |
| 表名 | 需排除系统表提示（可开关「显示系统对象」） | FROM/JOIN/UPDATE/INTO 之后 |
| 列名 | 当前上下文表中的列（含类型提示 `name varchar(255)`） | SELECT 列表 / WHERE / ON / SET 之后 |
| 表别名 | 解析当前语句中已声明的别名，`别名.` 后补全该表列名 | 输入 `别名.` |
| 限定补全 | `表名.` 后精确补全该表列名 | `table_name.` |
| 通配符展开（P1） | `SELECT *` 时提示展开为列清单 | 光标在 `*` 上 |
| 引号/括号配对 | 自动补全括号、单引号，`'` 内跳过补全 | 输入时 |

**智能规则**：

- 补全弹窗按「前缀匹配 > 模糊子序列匹配」排序；匹配字符高亮。
- 已声明别名后，裸列名补全优先匹配该别名表的列。
- 大写/小写输入决定补全项的大小写（输入 `sel` 补出 `select`；输入 `SEL` 补出 `SELECT`）。
- `Ctrl+Space` 手动触发；输入 `.`、空格、部分关键字时自动触发（可设置关闭自动触发）。
- 补全候选数据源：先查本地缓存 schema（对象树加载时缓存），缓存未命中时按需懒加载（带骨架屏/「正在加载」态），避免首次卡顿；大库（>1000 表）按 schema/表按需加载列，避免一次性拉全量。
- 版本感知：按服务器版本过滤补全项（MySQL 5.7 不提示 CTE/窗口函数；MSSQL 2016+；SQLite 3.35+ 才提示 `RETURNING`/`STRICT`）。
- 限定名：支持 MSSQL `db.schema.table` 三段式、MySQL `db.table`、SQLite `ATTACH` 库别名；各段均参与补全。
- 标识符：MySQL 反引号、MSSQL 方括号、SQLite 双引号；大小写与 `lower_case_table_names` 等服务器设置保持一致。
- DDL 语句上下文补全：`CREATE TABLE` 之后补表名；`ALTER TABLE` 之后补已有表名；`DROP TABLE` 之后同理。
- 容错降级：语句不完整时仍尽量补全；解析失败时降级为关键字/前缀补全，不阻塞输入（解析方案见 A.2）。

#### 4.2.3 编辑器通用能力

- 多标签页：每标签独立连接/库上下文、独立未保存内容；连接会话模型见 A.3-8（默认每标签独立连接，MSSQL 不依赖 MARS）。关闭未保存标签时确认保存（存为 `.sql` 或丢弃）。
- SQL 文件：支持新建/打开/保存/另存为 `.sql`，默认 UTF-8（可选 BOM）与 CRLF/LF；记录最近打开文件；支持拖入 `.sql` 文件打开。
- 语法高亮（按方言）、行号、当前行高亮、代码折叠（P1）、括号匹配、错误波浪线（解析失败处）。
- 格式化 SQL（快捷键或工具栏），可配置关键字大小写、缩进宽度；格式化库见 A.2。
- 选中片段执行：选中部分执行；未选中执行光标所在语句。分句按 `;`/`GO` 切分，并遵守 3.4 的分句规则（字符串、注释、`DELIMITER` 内不切分）。
- 多语句执行：按批依次执行，某批失败后停止后续批并展示逐批结果；MSSQL `GO` 各批在驱动层独立提交，MySQL 系/SQLite 的语句共享当前会话事务（若用户显式 `BEGIN`）。
- 参数化执行（P1，v1.x 规划）：识别 `?` / `:name` 占位符，执行前弹出参数面板；v1.0 未启用时对占位符给出明确提示。
- 执行统计：状态栏显示耗时、影响行数/返回行数。
- 查询超时中断：执行中按钮变为「取消」（P0 必须支持取消按钮；真正的服务端 cancel 视驱动能力，至少支持客户端断开等待）。
- 大结果集保护：默认最多拉取 1000 行（可配置 100/500/1000/5000/不限制），超出提示「仅显示前 N 行」，提供「导出全部」（流式写入，见 MOD-06）。

#### 4.2.4 异常与边界

- 超长 SQL（>1MB）：禁用补全与格式化，提示文件过大；执行时按语句分块提交，结果集流式读取。
- 补全数据过期：schema 变更（UI 改表后）自动失效并刷新缓存；对象树手动刷新亦触发失效。
- 解析失败：仅在可定位处标波浪线，不阻断编辑与执行；补全降级为关键字/前缀匹配。
- 未连接状态下：对象树与补全显示空态，编辑器可编辑但执行按钮禁用，悬停提示「请先连接」。

#### 4.2.5 验收标准（节选）

- AC: Given 已连接一个含 `users` 表的 MySQL 库，When 输入 `SELECT * FROM us`，Then 补全列表首位出现 `users`。
- AC: Given `SELECT u. FROM users u`，When 光标位于 `u.` 之后，Then 补全列表仅包含 `users` 的列。
- AC: Given 输入 `INS`，When 触发补全，Then 出现 `INSERT` 且插入为大写/小写与输入一致。
- AC: Given 执行一条 60 秒的查询（查询超时已设为 ≥60 秒），When 点击取消，Then 客户端停止等待并提示「已取消（服务端可能仍在执行）」。
- AC: Given 选中一段格式混乱的 SQL，When 按下 `Shift+Alt+F`，Then 按当前方言格式化且关键字大小写符合设置。
- AC: Given 编辑器中有 `SELECT 1; SELECT 2;`，When 执行全部，Then 结果区按语句展示两个结果集；若第二条失败，第一条结果保留并标记失败位置。
- AC: Given SQL 中包含字符串 `'a;b'` 或注释内的 `;`，When 执行当前语句，Then 分句器不得在字符串/注释内切分。
- AC: Given 打开一个 `.sql` 文件，When 修改后保存，Then 按原编码/换行保存并更新最近文件列表。

### MOD-03 查询历史（P0）

> 对应需求：**自动保存查询记录，查询记录支持根据查询内容搜索功能。**

#### 4.3.1 自动保存规则

- 触发时机：每次执行 SQL 都记录一条历史，无论成功、失败、被取消。
- 记录内容：

| 字段 | 说明 |
|---|---|
| id | 本地唯一 ID |
| sql_text | 完整 SQL 文本（原文保存，不改写） |
| db_type | sqlite / mysql / mssql |
| connection_id / connection_name | 所属连接快照（连接改名不影响历史展示） |
| database_name | 执行时的库名 |
| executed_at | 执行时间（系统时间） |
| duration_ms | 耗时 |
| status | success / failed / cancelled |
| error_message | 失败时的错误摘要（截断至 500 字符） |
| affected_rows / returned_rows | 影响/返回行数 |
| source | editor / ddl-preview / grid-edit（含单条自动提交与批量提交）/ agent-control |
| exec_count | 去重合并后的执行次数（关闭合并时恒为 1） |
| last_executed_at | 最后执行时间（列表默认按此倒序） |

- 去重策略（默认）：相同 `connection_id + sql_text` 在 60 秒内重复执行，合并为一条并累计 `exec_count`、更新 `last_executed_at`（可在设置中关闭合并，改为全部单独记录）。
- 存储上限：默认保留最近 **10,000** 条（设置可选 1,000 / 10,000 / 50,000 / 不限制），超限自动淘汰最旧；选择「不限制」时在超过 50,000 条后提示可能影响搜索性能，并仍走 FTS5 + `LIKE` 回退。
- 敏感内容：检测到 `PASSWORD` / `IDENTIFIED BY` / 行注释中的明显密钥字面量时，仍保存但列表默认脱敏显示（显示为 `***`），详情可切换显示；搜索仍匹配原文（可能暴露敏感内容存在性），导出/复制前弹窗提示。
- 清理：提供「清空全部历史」与「按连接清空」，删除时同步清理 FTS5 索引。
- 隐私：历史**仅存储在本机本地文件**，不出网、不上传；卸载时询问是否一并删除本地数据。

#### 4.3.2 搜索功能

- 入口：顶部工具栏「历史」按钮 / 快捷键 `Ctrl/Cmd + E` / 编辑器右键「从历史插入」。
- 主搜索框：按 **SQL 内容**全文搜索（包含匹配，大小写不敏感），输入防抖 200ms，结果高亮匹配文本。实现采用 FTS5 `trigram` 分词支持任意子串与中文；不可用时回退 `LIKE`（见 A.2）。
- 组合过滤：数据库类型、连接、库名、状态（成功/失败）、时间范围（今天/7天/30天/自定义）、来源（编辑器/DDL/网格/Agent 控制）。
- 结果展示：列表展示 时间 / 首行 SQL（截断）/ 类型图标 / 耗时 / 状态；默认按 `last_executed_at` 倒序，支持按时间/耗时排序。
- 列表操作（悬停/右键）：再次执行、插入到编辑器（光标处）、复制 SQL、仅看此连接、删除此条。
- 再次执行语义：原连接可用则直接执行并沿用原库；原连接不存在则插入编辑器并提示「原连接已删除，请选择目标连接」，不自动执行。
- 详情面板：点击条目查看完整 SQL（语法高亮）、错误详情；执行参数（P1，随 MOD-02 参数化执行在 v1.x 提供）。
- 空态：首次使用显示「执行任意 SQL 后，这里会自动保存记录」。
- 导出（P1）：导出为 `.sql` / `.csv` / `.json`，格式规范见 MOD-06 导出约定；导出前提示可能包含敏感数据。

#### 4.3.3 验收标准

- AC: Given 用户执行了 3 条不同 SQL，When 打开历史面板，Then 按时间倒序展示 3 条记录且含状态与耗时。
- AC: Given 历史中存在 `SELECT * FROM orders WHERE order_no = 'A123'`，When 搜索框输入 `A123`，Then 该条目出现在结果且 `A123` 高亮。
- AC: Given 连接已断开/已删除，When 打开历史，Then 历史仍可查看与搜索（显示连接名快照+「已删除」标记）。
- AC: Given 历史已满 10,000 条，When 再执行一条新 SQL，Then 最旧的一条被淘汰，总数保持 10,000。
- AC: Given 同一 SQL 在 60 秒内执行 3 次，When 打开历史，Then 仅 1 条记录且 `exec_count = 3`、时间显示最后一次执行。
- AC: Given 用户点击「清空历史」，When 二次确认，Then 全部历史删除、FTS5 索引清理且 UI 立即刷新为空态。
- AC: Given 历史中包含中文或子串 `123` 的 SQL，When 搜索 `123`，Then 能按包含匹配命中（不依赖分词边界）。

### MOD-04 UI DDL 操作（P0）

> 对应需求：**支持 UI 的 DDL 操作。**

#### 4.4.1 设计原则

1. **所见即所得 + SQL 预览**：任何 UI 修改先生成 DDL 预览，用户确认后执行；预览可手动编辑（编辑后以编辑内容为准执行）。
2. **安全优先**：DROP/删除列/改类型（可能丢数据）必须二次确认并输入对象名确认。
3. **方言透明**：UI 统一概念模型（表/列/索引/约束），生成 SQL 时翻译为三方言语法。
4. **可审计**：DDL 执行后自动写入查询历史（source = ddl-preview）。

#### 4.4.2 功能清单

| 操作 | 说明 | SQLite | MySQL 系 | MSSQL |
|---|---|---|---|---|
| 新建表 | 向导：表名、列、主键、索引、注释 | ✓（SQLite 不支持表/列注释，注释字段置灰） | ✓ | ✓ |
| 编辑表结构 | 统一「设计视图」：左列列表 + 右侧属性面板 | ✓（原生 ALTER + 必要时重建表，见 4.4.4） | ✓（ALTER TABLE） | ✓（ALTER TABLE） |
| 添加列 / 删除列 / 重命名列 | 属性面板直接操作 | ✓（3.35+ 删列；低版本/改类型需重建表） | ✓ | ✓ |
| 修改列类型/长度/可空/默认值/自增 | 类型下拉按方言过滤 | 部分（重建表） | ✓ | ✓ |
| 重命名表 / 删除表 | 右键菜单 + 对象树 | ✓ | ✓ | ✓ |
| 索引管理 | 新建（唯一/普通/组合）、删除、查看；高级类型（前缀索引、函数索引、MSSQL INCLUDE、部分索引）按方言能力显示 | ✓（部分索引） | ✓（前缀/函数索引） | ✓（INCLUDE/筛选索引） |
| 主键/外键/唯一约束 | 新建、删除（含 `ON DELETE` / `ON UPDATE` 级联动作选择） | ✓（外键 PRAGMA） | ✓ | ✓ |
| 检查约束（CHECK） | 新建、删除、查看；表达式按方言校验 | ✓ | ✓ | ✓ |
| 表注释 | 设置/查看 | —（置灰） | ✓ | ✓（扩展属性） |
| 视图/触发器（P1） | 列表+源码查看、创建/删除 | ✓ | ✓ | ✓ |
| 生成建表 SQL 导出 | 对象树右键「生成 DDL」 | ✓ | ✓ | ✓ |

#### 4.4.3 建表/改表向导交互

- 设计视图顶部：表名（可重命名）、表注释。
- 列网格：列名 | 类型（下拉）| 长度/精度 | 可空（checkbox）| 默认值 | 自增 | 主键 | 注释；行支持拖拽排序（决定列顺序，仅对新建表生效）。
- 底部页签：索引 / 外键 / 检查约束 / 选项（MySQL 引擎/字符集/排序规则）。
- 校验：表名/列名非法字符即时标红；重复列名/索引名；主键建议填写（允许无主键，但提示「无主键表将默认只读」）；默认值类型匹配（数字列默认值不能为字符串）；自增列必须是整数类型且有索引；外键引用的表/列必须存在；生成列/计算列只读。
- 保存流程：点击「保存」→ 生成 DDL 预览弹窗（语法高亮、可编辑、标注方言与事务能力）→ 「取消 / 执行」→ 执行后刷新对象树并写入历史。
- 部分失败：多语句执行中某一条失败，展示逐条结果（成功/失败+原因）。事务策略按方言区分：MSSQL/SQLite 在支持事务的 DDL 上整体回滚；MySQL 系 DDL 隐式提交，无法回滚，提示「已执行部分变更，请检查」并列出已成功语句。

#### 4.4.4 SQLite 特殊约束（产品提示而非隐藏）

SQLite 的 DDL 能力随版本差异较大：3.35+ 支持 `DROP COLUMN`，3.25+ 支持 `RENAME COLUMN`，但**修改列类型/长度/可空/默认值/列重排**仍需重建表。产品策略：

- 优先使用原生 `ALTER TABLE`：重命名表/列、增加列、3.35+ 删列；仅在必要时（改类型/改约束/列重排/低版本）走重建表。
- 重建表序列（全部显示在预览弹窗中）：
  1. `PRAGMA foreign_keys=OFF`（事务外）；
  2. `BEGIN`；
  3. `CREATE TABLE __new_<table> (...)`；
  4. `INSERT INTO __new_<table> (...) SELECT ... FROM <table>`；
  5. `DROP TABLE <table>`；
  6. `ALTER TABLE __new_<table> RENAME TO <table>`；
  7. 重建**索引、触发器、视图**，恢复 `sqlite_sequence`（AUTOINCREMENT）；
  8. `PRAGMA foreign_key_check`；
  9. `COMMIT`；
  10. `PRAGMA foreign_keys=ON`。
- 外键：新表 DDL 保留原表外键定义；其他表引用旧表的外键在重命名后仍指向同名表；`foreign_key_check` 有结果则回滚。
- 依赖对象必须一起处理：重建前从 `sqlite_master` 读取索引、触发器、视图定义，预览中列出将重建的对象；无法解析/重建的对象阻止执行并提示原因，不静默丢弃。
- 执行期间对该数据库文件加应用级维护锁，暂停/排队其他会话的写操作；显示「正在重建表…」进度并支持取消（取消即回滚）。
- 预览中用警告色提示「此操作会重建表，大表耗时较长，建议先备份」。
- `WITHOUT ROWID`、生成列、严格表（STRICT）、复杂默认值：按数据库原生能力处理；无法安全重建时阻止执行并提示改用 SQL。

#### 4.4.5 预览弹窗规范

- 标题：将执行的 DDL（N 条语句）+ 方言标识。
- 内容：完整 SQL，可编辑，提供「恢复为 UI 生成结果」按钮。
- 警告区：检测到 DROP/重建表/改小类型/删除非空列 时列出风险项；并标注该方言的 DDL 事务能力（可回滚 / 隐式提交不可回滚）。
- 按钮：取消 / 执行。执行成功 toast + 刷新对象树；部分失败时展示逐条结果。

#### 4.4.6 验收标准（节选）

- AC: Given 打开 MySQL 连接，When 右键「表」→「新建表」填写 `orders`（含 id 自增主键 + order_no varchar(64) 唯一索引），Then 预览弹窗展示含 `CREATE TABLE`、`AUTO_INCREMENT`、`UNIQUE` 的 MySQL DDL，执行后对象树出现 `orders`。
- AC: Given 在设计视图把 `email` 列类型从 `varchar(64)` 改为 `varchar(32)`，When 保存，Then 预览含 `ALTER ... MODIFY` 且警告「可能截断数据」。
- AC: Given SQLite 3.35+ 表删除一列，When 保存，Then 预览为 `ALTER TABLE ... DROP COLUMN`；Given 低版本或改类型，When 保存，Then 预览为重建表序列并带警告，确认后执行成功、数据保留、索引重建。
- AC: Given SQLite 表带有索引、触发器、视图和外键，When 执行重建，Then 预览包含索引/触发器/视图重建 SQL，执行后全部对象存在且 `PRAGMA foreign_key_check` 无结果。

- AC: Given MSSQL 表重命名列，When 保存，Then 预览含 `sp_rename` 且保留原列类型/约束。
- AC: Given 新建 CHECK 约束，When 保存，Then 预览含 `CONSTRAINT ... CHECK (...)`，非法表达式在保存前标红。

### MOD-05 表数据增删改（P0）

> 对应需求：**支持 UI 的表数据的增删改。**

#### 4.5.1 功能描述

以网格形式浏览表数据，支持单元格直接编辑、新增行、删除行、批量操作，并在事务中提交或回滚。

#### 4.5.2 网格能力

- 数据浏览：双击表打开（对象树双击 / 右键「查看数据」），采用**显式分页**（默认 200 行，可选 50/200/500/1000），翻页/跳页；RevoGrid Core 自带行/列虚拟化，不另做滚动加载。结果集页签的拉取上限见 MOD-06。
- 列显示：列宽可拖拽、可隐藏列、固定前 N 列；列头显示类型（悬停 tooltip）；列显示偏好按表记忆。
- 排序：点击列头升序/降序/取消（生成 `ORDER BY`）；支持 `Shift+点击` 多列排序，列头显示序号。
- 过滤：列头过滤框按类型提供操作符——文本（包含/等于/开头/结尾/IN）、数字（=/≠/>/≥/</≤/区间）、日期（区间/相对时间）、布尔；多条件 AND；等价 WHERE 显示在顶部条件栏，可手动编辑后回车应用（语法错误标红，不执行）。自动生成的过滤条件使用参数化；手动编辑的 WHERE 由用户自行负责，执行前提示。
- 单元格编辑：双击或 `F2` 进入编辑；按类型呈现编辑器——文本、数字、日期/时间选择器、布尔勾选、枚举下拉（CHECK 枚举 / MySQL ENUM，P1）、大文本弹窗编辑器。计算列/生成列/`rowversion`/`timestamp` 列只读。
- 主键编辑：默认禁止修改主键列；确需修改时需二次确认，并说明可能影响外键与行定位。
- 自增列：新增行默认留空由数据库生成；需显式写入时开启「允许显式插入自增列」（MSSQL `SET IDENTITY_INSERT`）。
- 默认值：新增行单元格留空表示使用列默认值；显式 NULL 需右键「设为 NULL」，两者在 UI 与提交 SQL 中区分。
- NULL 编辑：右键菜单「设为 NULL / 取消 NULL」，NULL 单元格显示灰色斜体 `NULL`。
- BLOB/大文本（>10KB）：单元格显示摘要（如 `<BLOB 2048 bytes>` / 前 100 字符），双击打开查看器；v1.0 查看器只读，不支持编辑二进制，支持 hex 查看（P1）。
- 新增行：工具栏「+」按钮追加空行（或「复制当前行」），必填列（NOT NULL 无默认值）高亮提示。
- 删除行：选中一/多行，工具栏删除或 `Delete` 键；删除前若处于自动提交关闭状态，仅标记删除（红底划线），提交后生效；批量删除需展示将执行的 DELETE 语句。
- 粘贴：支持从 Excel/TSV 粘贴多行多列到网格，按列类型校验后进入待提交状态。
- 撤回栈：提交前支持 `Ctrl+Z` 撤销单元格/行操作（会话内）；提交后清空撤销栈。

#### 4.5.3 事务模型（关键）

- 默认「安全提交」模式：编辑不立即写库，网格进入「有未提交更改」状态，工具栏出现「提交 / 回滚」按钮与更改计数（如 `+3 改 5 删 1`）。
- 提交：在单一事务内生成批量 `UPDATE/INSERT/DELETE` 并执行，语句顺序为 DELETE → UPDATE → INSERT（减少唯一键冲突）；成功 toast「已提交 N 项更改」并清空标记；任一行失败则**整批回滚**，高亮冲突单元格，不产生部分提交。
- 冲突预检：提交前先对冲突行做预检；用户选择「跳过冲突行」时，将冲突行从本次提交集合中排除后整体提交，其余行成功、冲突行保持标记，不产生部分事务。
- 回滚：丢弃全部未提交更改，网格还原。
- 快捷模式（设置项「自动提交单元格编辑」，默认关闭）：每次编辑即执行单条 UPDATE/INSERT/DELETE，失败不回滚已成功的其他单元格。
- 会话模型：网格提交使用独立连接/独立事务，不与编辑器标签的手动 `BEGIN` 共享；SQLite 等单写库串行排队并提示等待。
- 关闭保护：有未提交更改时关闭标签/断开连接/退出应用，弹窗确认「提交 / 丢弃 / 取消」。
- 失败处理：锁等待超时/死锁给出可读提示并允许重试；连接中断时保留未提交更改并标记「连接已断开」，重连后可重新提交。
- 乐观锁：UPDATE/DELETE 的 WHERE 默认包含主键 + 可用的原值比较（MSSQL 优先 `rowversion`；MySQL 系/SQLite 比较非主键列原值），防止「他人改了非主键列但主键仍匹配」导致的丢失更新。大字段/无可靠比较列时降级为主键匹配并在提交前提示风险。

#### 4.5.4 无主键表的限制

- 无主键/唯一非空列的表：默认**只读**，顶部黄条提示「该表无主键，出于安全考虑请通过 SQL 编辑更新数据」，提供「我知道风险，仍要编辑」开关（按表记录到本地设置）。
- 开启风险编辑后，使用所有列原值做 WHERE 定位行；该模式性能差且仍可能误改重复行，提交前必须展示 SQL 并二次确认。
- SQLite 的 `rowid` 表可在确认机制下允许编辑（使用 `rowid` 作为行标识）；`WITHOUT ROWID` 表按无主键表处理。

#### 4.5.5 导出/复制

- 选中行 / 全部结果集：导出 CSV / JSON / SQL Insert 语句；复制为 TSV（粘贴到 Excel）。
- 导出遵循 MOD-06 的统一导出规范：CSV 默认 UTF-8 BOM、NULL 与空串区分、日期 ISO 8601、二进制 Base64/Hex 可选；大结果集流式写文件，提供进度与取消。

#### 4.5.6 验收标准（节选）

- AC: Given 打开 `users` 表网格，When 双击 `name` 单元格修改后按 Enter，Then 单元格标记为已修改且工具栏出现「提交/回滚」，数据库未被立即写入。
- AC: Given 已修改 2 行、新增 1 行、删除 1 行，When 点击「提交」，Then 三类操作在一个事务中执行成功，网格清除标记。
- AC: Given 同一行已被其他会话修改，When 本网格提交 UPDATE，Then 检测到原值不一致/0 行受影响，弹窗提示冲突且该行保持标记，其他行可整体回滚或排除冲突后提交。
- AC: Given 有未提交更改，When 用户关闭窗口，Then 弹出确认框，可选提交/丢弃/取消。
- AC: Given 过滤 `status = 'paid'` 且排序 `created_at DESC`，When 点击提交，Then 生成的 UPDATE 仅包含过滤条件对应的 WHERE，不包含 ORDER BY，数据正确刷新。
- AC: Given 提交 2 条更改且第 2 条触发唯一键冲突，When 提交失败，Then 整个事务回滚，第 1 条也不生效，冲突行高亮。
- AC: Given 双击主键单元格，When 尝试修改，Then 默认只读并提示需二次确认。
- AC: Given 从 Excel 复制 3 行 4 列并粘贴到网格，When 粘贴完成，Then 生成 3 条待提交新增行且类型校验失败的单元格标红。

### MOD-06 结果集与输出（P0）

#### 4.6.1 结果集展示

- 单次拉取上限默认 1000 行（可在 MOD-07 配置 100/500/1000/5000/不限制）；超出提示「仅显示前 N 行」，提供「导出全部」。
- 表格结果：等宽字体、数字/日期右对齐、行号列、斑马纹、NULL 灰色斜体、大字段截断+查看器。
- 结果页签：每条语句一个结果集页签，标注语句序号与耗时；无结果集的语句进入消息面板。
- 列操作：排序（支持多列）、列宽调整、复制选中区域（TSV/CSV）、复制列名。
- 大结果集不随行数线性占用内存：分页/流式读取，导出走流式写文件（见 4.6.3）。

#### 4.6.2 多结果集与消息

- MSSQL：`GO` 分批，每批结果独立页签；`PRINT` / `RAISERROR` / 警告进入消息面板。
- MySQL 系：启用多语句时按语句返回多结果集；warning 进入消息面板。
- SQLite：多语句仅返回最后一条语句的结果集，其余执行结果以消息形式展示（执行前提示该差异）。
- 消息面板：非查询语句（UPDATE/DDL）显示「影响 N 行 / 执行成功」；错误显示红色详情。
- 错误信息：MySQL 系/MSSQL 展示 SQLSTATE + 原生错误码 + message；SQLite 展示 result code + message（无 SQLSTATE，不伪造）。
- 执行计划（P2，v1.x）。

#### 4.6.3 导出约定

- 格式：CSV / JSON / Excel(.xlsx，P1) / SQL Insert；支持选中区域、当前结果集、全部结果集。
- CSV：默认 UTF-8 with BOM（Excel 中文兼容），逗号分隔，双引号转义，CRLF；可选分隔符与是否含表头。
- NULL 与空串：CSV 中 NULL 输出为空字段并在导出选项中选择是否加 `\N` 标记；JSON 中 NULL 为 `null`、空串为 `""`。
- 日期/时间：按数据库返回值输出；有时区类型保留原偏移，无时区类型不添加时区，不做应用层转换；二进制：Base64（默认）或 Hex。
- SQL Insert：按方言生成标识符引号、字符串转义、`N''`（MSSQL Unicode）、NULL、自增列处理；大文件分批写入。
- 大导出：流式写入临时文件后原子替换，显示进度与取消；超过 100MB 提示预计大小。
- Excel：P1，使用 SheetJS 生成 `.xlsx`；RevoGrid Core 不内置 Excel 导出，不依赖商业 Grid。

#### 4.6.4 验收标准（节选）

- AC: Given 查询返回 5,000 行且上限为 1,000，When 执行，Then 仅展示前 1,000 行并提示「仅显示前 1,000 行」，可点击「导出全部」。
- AC: Given MSSQL 脚本包含两个 `GO` 批，When 执行，Then 结果区出现两个结果页签，消息按批展示。
- AC: Given MySQL 系多语句中第二条失败，When 执行，Then 第一条结果保留，消息面板显示第二条的 SQLSTATE 与错误信息。
- AC: Given 导出包含 NULL、空串、中文、日期的结果集为 CSV，When 用 Excel 打开，Then 中文不乱码、NULL 与空串可区分、日期格式正确。
- AC: Given 导出 50 万行结果集，When 导出，Then 界面不卡死、显示进度、可取消，取消后不留下半截目标文件。

### MOD-08 MSSQL Agent 作业（Jobs）（P0，仅 MSSQL）

> 对应需求：**支持 MSSQL 的 SQL Server Agent，支持 Jobs。**

#### 4.8.1 定位与设计原则

**监控 + 脚本化编辑 + 生命周期控制**：作业的启动/停止/启用/禁用通过列表与详情页按钮直接完成（调用 Agent 存储过程）；作业配置（步骤、计划、命令、描述等）的新增/修改仍通过右键「编辑」生成可读、可 diff 的 ALTER 脚本，交给编辑器执行——复用编辑器的补全、格式化、GO 分批执行、查询历史与事务能力，避免 UI 双通道分叉。不做 UI 创建/编辑向导。

- 按钮只做生命周期控制，不修改步骤/计划/命令内容；所有配置变更仍走 SQL 脚本。
- SQLite / MySQL 系不显示本节点；
- v1.0 仅支持 Jobs，不含 Operators / Alerts / Proxies，不含多服务器（MSX/TSX）集中管理；
- **薄 UI 原则：不做任何自定义权限判断**，直接用当前连接账号读写 `msdb`，权限不足/Agent 未启用/Agent XPs 禁用等情况，原样透传 MSSQL 原生错误并附一句可读提示。
- 所有启停/启用/禁用操作写入查询历史（`source = agent-control`），记录生成的存储过程调用与实际结果，保证可追溯。

#### 4.8.2 信息架构与入口

- 对象树：MSSQL 连接节点下新增 **「SQL Server Agent」** 节点（仅 MSSQL 连接显示），其下仅有 **「作业」** 子节点。
- 双击「作业」→ 在主区域打开「作业列表」页签（监控视图，支持生命周期操作；与 SQL 标签并列，可多开）。
- 作业列表工具栏与作业详情头部提供 **启动 / 停止 / 启用 / 禁用** 按钮；按钮按选中作业状态启用/禁用，操作期间置灰防重复点击。

#### 4.8.3 作业列表（监控 + 生命周期操作）

数据源：直接执行 T-SQL 查询 `msdb`（不依赖 SMO）：

| 列 | 来源 |
|---|---|
| 名称 | `msdb.dbo.sysjobs.name` |
| 已启用 | `sysjobs.enabled` |
| 类别 | `sysjobs.category_id` → `syscategories` |
| 上次运行结果 | `sysjobhistory` 中 `step_id = 0` 的最近一条（作业级结果，`run_status`）；无记录显示「从未运行」 |
| 上次运行时间 | 同上（`run_date` + `run_time`） |
| 耗时 | 同上 `run_duration`（hhmmss 转秒）；无记录显示 `—` |
| 下次运行 | `sysjobschedules.next_run_date/time`（按 `schedule_id` 关联 `sysschedules`）；Agent 停止时该值可能过期，悬停提示 |
| 所属者 | `sysjobs.owner_sid` → `SUSER_SNAME()` |

- 顶部：名称搜索框（防抖过滤）、刷新按钮（手动）、启动/停止/启用/禁用按钮；P1：30s 自动刷新开关、「仅看失败」过滤。
- 排序：默认按名称；可切换按上次运行时间。
- 运行状态（P1）：基于 `sysjobactivity`/`syssessions` 展示「运行中/空闲」；v1.0 未启用时以最近一次操作结果与刷新判断。
- 双击行 → 打开作业详情页签；右键 → 启动/停止/启用/禁用、「编辑（在编辑器中打开）」、「复制作业名」、「复制步骤命令」（P1）。
- 生命周期操作规则：
  - 启动：作业处于禁用状态时提示「请先启用」；启动请求成功后刷新列表。
  - 停止：二次确认（会中断当前运行）；停止请求成功后刷新列表。
  - 启用/禁用：禁用需二次确认（后续计划不再运行）；成功后更新列表状态。
  - 操作期间按钮置灰，防止重复提交；失败时透传原生错误，不改变本地状态。
- 作业数量大（>1000）：服务端分页/`TOP` + 虚拟滚动 + 搜索收敛，不一次性拉全量。
- 权限：查看需要 `SQLAgentReaderRole`（或更高）；启停/启用/禁用通常需要 `SQLAgentOperatorRole` 或作业所属者权限；无权限时按 4.8.6 透传错误。

#### 4.8.4 作业详情（独立页签，内容只读 + 生命周期操作）

- **基本信息**：名称、描述、启用状态、类别、所属者、创建/修改日期。
- **步骤列表**：步骤序号 | 步骤名 | 子系统（T-SQL / PowerShell / SSIS / CmdExec…）| 成功动作 / 失败动作 | 命令（截断预览）；含「在编辑器中打开此命令」入口（仅带出文本，**不自动执行**）。
- **计划列表**：计划名、启用状态、频率描述、间隔、下次运行时间。频率描述覆盖 `freq_type` 的常见取值（一次性/每日/每周/每月绝对/每月相对/空闲/开机/登录等）及 `freq_interval`/`freq_recurrence_factor`/`freq_relative_interval`；无法解析的组合显示原始字段并标注「复杂计划，请用 SSMS 查看」。
- **运行历史**：按 `sysjobhistory` 倒序展示最近 **100 条**（可设置 100/500），含步骤名、结果（成功/失败/重试/取消）、执行时间、耗时、消息；失败消息红色高亮，超长消息截断并可展开；表头提示「更多历史请直接查 msdb.dbo.sysjobhistory」。
- 详情页头部：「启动 / 停止 / 启用 / 禁用」+「编辑」；「编辑」= 右键同款，生成脚本并在编辑器中打开，不自动执行。

#### 4.8.5 脚本化编辑（核心能力）

> 启停/启用/禁用属于生命周期控制，不生成也不修改配置脚本；本节只描述作业配置的脚本化编辑。

右键「编辑（在编辑器中打开）」生成完整 ALTER 风格脚本，示例骨架：

```sql
-- 由 DBCraft 生成（Job: <name>，<生成时间>）。
-- 修改下方脚本后请核对再执行。新增步骤/计划请改用 sp_add_* 系列。
USE msdb
GO
EXEC dbo.sp_update_job @job_name = N'<name>', @enabled = 1, @description = N'...', ...
GO
EXEC dbo.sp_update_jobstep @job_name = N'<name>', @step_id = 1, @step_name = N'...',
     @subsystem = N'TSQL', @command = N'...', @on_success_action = 1, @on_fail_action = 2, ...
GO
EXEC dbo.sp_update_schedule @schedule_name = N'<schedule>', @freq_type = 4, @freq_interval = 1, ...
GO
```

规则：

- **编辑范围**：作业属性（启用、描述、类别、所属者、通知）、已有步骤（名称、子系统、命令、成功/失败动作、重试）、已附加计划。新增/删除步骤或计划不生成破坏性语句，仅在注释中给出 `sp_add_jobstep` / `sp_delete_jobstep` / `sp_add_schedule` / `sp_attach_schedule` / `sp_detach_schedule` 的改法。
- **启用状态**：脚本中的 `@enabled` 与列表「启用/禁用」按钮等价；按钮操作即时生效，脚本执行后同样以数据库状态为准。
- **步骤定位**：`sp_update_jobstep` 使用生成时的 `@step_id` 快照；若用户脚本中增删/重排步骤，需自行调整后续 `@step_id`，脚本头部注明该约束。
- **共享计划**：`sp_update_schedule` 会修改被多个作业共享的计划。生成前按 `schedule_id` 统计 `sysjobschedules` 的引用数；共享计划必须警告「此修改将影响其他作业」，并建议改用 `sp_add_schedule` + `sp_attach_schedule` + `sp_detach_schedule` 创建作业私有计划。
- **命令文本**：原样保留（多行、单引号转义为 `''`、Unicode 加 `N` 前缀），不丢失用户内容；字符串/注释内的 `GO` 不触发切分（由分句器保证）。
- 方言识别为 MSSQL，`GO` 作为批分隔符（编辑器分句/执行器已支持）。
- 生成的脚本是普通编辑器标签：可用补全、格式化、选中执行、历史记录；执行后由用户手动点列表「刷新」（Agent 页签 P1 提供 30s 自动刷新）。
- 脚本头部包含：生成时间、作业名、共享计划警告、编辑范围说明、以及「执行前请核对」提示。

#### 4.8.6 权限与错误处理（薄 UI，不自定义权限判断）

- 不预探测权限、不做角色/阈值判断；SQL 执行失败时：**原样展示 MSSQL 原生错误码与 message**，下方附一句通用提示：
  > 「当前账号可能对 msdb 无访问权限（只读查看通常需要 SQLAgentReaderRole；启停/启用/禁用通常需要 SQLAgentOperatorRole 或作业所属者权限），或 SQL Server Agent 未启用 / Agent XPs 已禁用，请联系 DBA 或调整连接账号后重试。」
- 启停/启用/禁用失败时同样原样展示原生错误码与 message，不把权限失败伪装成「操作成功」。
- Agent XPs 禁用时，提示中附启用方式（仅提示，工具**不代为执行**）：`sp_configure 'show advanced options', 1; RECONFIGURE; sp_configure 'Agent XPs', 1; RECONFIGURE;`
- Agent 服务停止：列表刷新报错时同上处理，不显示「假空状态」；
- 不查询 `sys.dm_server_services`（避免额外 VIEW SERVER STATE 依赖）。

#### 4.8.7 边界与不支持

- 检测到多服务器作业（`sysjobs` 关联非本地 `sysjobservers`）：列表标注「[多服务器]」只读展示；启停/启用/禁用按钮禁用（避免误操作目标服务器）；"编辑"仍可生成本地脚本但头部注释警告「多服务器作业请使用 SSMS 管理」；
- 步骤子系统非 T-SQL（PowerShell / SSIS / CmdExec）：仅展示与复制命令，无自动执行入口；
- Agent 服务停止 / Agent XPs 禁用：列表报错且启停/启用/禁用按钮禁用，不显示假状态；
- 作业历史巨大：列表不滚动加载全部，固定最近 100/500 条；
- Job 配置变更产生的执行：与在编辑器执行的普通脚本一致，进入查询历史（source = editor）。
- 生命周期操作：启动/停止/启用/禁用写入查询历史（source = agent-control），与配置脚本区分。

#### 4.8.8 验收标准（AC）

- AC: Given MSSQL 连接且 Agent 正常，When 展开「SQL Server Agent → 作业」，Then 展示作业列表（名称、启用状态、上次运行结果/时间、耗时）。
- AC: Given 双击某作业，When 打开详情，Then 展示基本信息、步骤、计划、最近 100 条运行历史，失败消息红色高亮。
- AC: Given 右键「编辑（在编辑器中打开）」，When 生成脚本，Then 新标签包含 `USE msdb` + `GO` + `sp_update_job`/`sp_update_jobstep` 且方言为 MSSQL，可直接选中执行。
- AC: Given 当前账号无 msdb 权限，When 打开作业列表，Then 显示 MSSQL 原生错误 + 一句可读提示，UI 不崩溃、不假空。
- AC: Given SQLite / MySQL 系连接，When 展开对象树，Then 不出现 SQL Server Agent 节点。
- AC: Given CmdExec 步骤的作业，When 查看详情，Then 命令文本可查看/复制，界面无任何自动执行入口。
- AC: Given 作业的 T-SQL 步骤，When 点击「在编辑器中打开此命令」，Then 编辑器新标签带出完整命令，用户手动决定是否执行。
- AC: Given 作业最近一次运行包含多个步骤，When 查看列表「上次运行结果」，Then 取 `step_id = 0` 的作业级结果，而不是某个步骤的结果。
- AC: Given 作业使用被其他作业共享的计划，When 右键「编辑」，Then 脚本生成前弹出共享计划警告，并建议改用 `sp_add_schedule` + `sp_attach_schedule`。
- AC: Given 只读账号仅具备 SQLAgentReaderRole，When 打开作业列表/详情，Then 可正常查看；When 执行 ALTER 脚本或点击启停按钮，Then 透传权限不足的原生错误。
- AC: Given 选中一个空闲作业，When 点击「启动」，Then 调用 `sp_start_job` 并在成功后刷新列表；操作写入查询历史（`source = agent-control`）。
- AC: Given 一个作业正在运行，When 点击「停止」并确认，Then 调用 `sp_stop_job`，成功提示「已请求停止」并刷新状态。
- AC: Given 一个已禁用作业，When 点击「启动」，Then 提示「请先启用」且不发起启动请求。
- AC: Given 点击「禁用」并确认，When 操作成功，Then 列表「已启用」列变为否；再次点击「启用」恢复。
- AC: Given 连续快速点击「启动」两次，When 第一次请求未完成，Then 第二次点击被置灰拦截，不重复调用。
- AC: Given 多服务器作业，When 查看列表/详情，Then 启停/启用/禁用按钮禁用，仅保留脚本编辑入口。

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
|---|---|
| 启动到可操作（冷启动） | < 3s（SSD，不含大数据目录） |
| 启动到可操作（热启动） | < 2s（SSD） |
| 打开 10 万行表首屏 | < 1s（分页查询） |
| 对象树加载 1,000 张表 | < 2s（懒加载，列按需） |
| DDL 生成（单表） | < 100ms |
| 历史 10,000 条搜索响应 | < 100ms（FTS5）；「不限制」模式下 >50,000 条允许降级至 <500ms |
| 补全弹窗弹出 | < 100ms（缓存命中）/ < 500ms（懒加载） |
| 内存占用 | 常驻基线 < 300MB（Electron + Monaco + RevoGrid，实测校准）；不随结果集大小线性增长（分页/流式） |
| 历史写入 | 异步，不阻塞结果展示（P95 < 50ms） |

### 5.2 稳定性

- 崩溃可恢复：编辑器未保存内容每 30s 自动存入本地草稿，退出前强制落盘；重启后提示恢复。
- 任何 SQL 崩溃不影响工具进程：驱动异常被捕获，展示错误而非闪退。
- 提供「诊断日志」导出（不含密码与 SQL 文本；错误消息先做脱敏）。
- 单实例运行；元数据库升级前自动备份，损坏时可回退到最近备份。
- 崩溃统计：v1.0 **不内置远程崩溃上报**；通过本地匿名统计面板 + 用户主动导出度量（见 §6），任何上传必须 opt-in。

### 5.3 安全与隐私

- 连接密码本地**加密存储**（系统密钥链优先：Windows DPAPI / macOS Keychain / libsecret；不可用时回退为 AES-GCM 文件 + 主密钥提示）。主密码遗忘时只能重置并重新输入数据库密码，不提供找回。
- 历史 SQL 可能含敏感数据：默认脱敏展示（见 MOD-03），不上传网络，不参与崩溃上报。
- **静态数据边界**：v1.0 历史与元数据库为本地 SQLite 明文文件，依赖操作系统账户隔离与磁盘加密；不在产品内承诺历史内容加密，SQLCipher 列入 v1.x 评估。威胁模型（本机多用户、磁盘丢失）在安全文档中说明。
- 日志不记录 SQL 文本（仅记录耗时/状态/错误码）；错误消息入库前脱敏。
- 渲染进程到主进程的 IPC 全部校验参数类型与长度，禁止渲染层拼接任意 SQL 执行路径（DDL/DML 均走结构化请求）。
- 导出历史/导出结果时，弹窗提示「文件将包含完整数据」。

### 5.4 兼容性

- 操作系统：Windows 10（1809+）/11（首发）、macOS 12+（P1）、Linux（P1）。
- 数据库版本：
  - SQLite 3.35+（驱动内置，含 WAL 模式；低版本降级为重建表）
  - MySQL 5.7 / 8.0 / 8.4
  - Percona 8.0 / 8.4
  - MariaDB 10.3+（独立连接/认证；类型、DDL、函数等差异按数据库原生行为透传）
  - MSSQL 2016 / 2017 / 2019 / 2022；Azure SQL 未认证（Agent 节点不显示）
  - 说明：MySQL 5.7、MariaDB 10.3 已 EOL，仅保留冒烟覆盖，不承诺额外兼容层
- 版本能力差异见 3.4；架构与具体选型见附录 A（v0.15）。

### 5.5 可用性/无障碍

- 全键盘可操作（焦点顺序合理、快捷键覆盖核心路径）；Monaco 与 RevoGrid 的焦点进入/离开有明确指示，不产生焦点陷阱。
- 颜色对比度满足 WCAG AA（深/浅两主题）；使用自动化对比度检查 + 人工抽查。
- 屏幕阅读器：表格提供行列标题与单元格类型描述，编辑器提供文档结构；v1.0 以 NVDA 抽查核心路径。
- 支持 Windows 高 DPI 与多显示器缩放（100%/125%/150%）。
- 错误文案可读：避免裸驱动报错，映射为中文+原错误并列展示；映射覆盖连接、认证、超时、权限、语法、约束冲突六类。

#### A.3 架构与关键设计

1. **进程模型与安全基线**：所有数据库驱动与密码仅存在于主进程；渲染进程 `nodeIntegration=false, contextIsolation=true, sandbox=true`；渲染层通过 `contextBridge` 暴露的 typed IPC（`invoke/handle`）调用；结果集默认分页拉取（单次上限 1000 行，表数据页 200 行/页），大结果集流式分块传输，避免 IPC 大对象卡顿；DDL/危险操作确认均在渲染层完成，但执行权只在主进程。
2. **方言抽象层 `Dialect`**：SQLite / MySQL 系 / MSSQL 差异收敛为统一接口——`paginate()`、`quoteIdent()`、`buildCreateTable()` / `buildAlterTable()`、类型与默认值映射、注释、自增列等；MySQL 系内部再按 MySQL / Percona / MariaDB 区分连接与认证。UI 层不含任何方言分支。这是后续新增 PostgreSQL 等数据库的唯一扩展点。
3. **历史写入异步化**：查询返回后异步写元数据库，不阻塞结果展示；相同 `connection_id + sql_text` 在 60 秒内合并为一条并累计 `exec_count`（可关闭）。
4. **schema 缓存**：对象树/补全共用内存缓存（库→表→列），补全弹窗走缓存（<100ms）；缓存未命中时懒加载并显示「正在加载」；DDL 执行成功、对象树手动刷新后精确失效。
5. **未保存保护**：编辑器内容每 30 秒写入元数据库草稿区，异常退出后重启可恢复。
6. **查询执行与取消**：执行器支持超时（可配置）；取消按钮至少做到客户端停止等待并提示，服务端 cancel 随驱动能力增强（MySQL 系支持 `KILL QUERY`；MSSQL 依赖驱动 cancel）。
7. **性能预算**：冷启动 <3s / 热启动 <2s；10k 历史 FTS5 搜索 <10ms；补全 <100ms；常驻内存基线 <300MB（实测校准）。
8. **会话与事务模型**：默认每个 SQL 标签使用**独立连接**（来自连接池），避免 MSSQL 无 MARS 时的请求互斥；网格编辑使用独立连接/独立事务，不与编辑器手动 `BEGIN` 共享；SQLite 单写库串行排队。
9. **类型映射**：`Dialect.typeMap` 统一「数据库类型 ↔ UI 编辑器 ↔ 导出格式」；`BIGINT`/`DECIMAL` 以字符串传输避免 JS 精度丢失；二进制以 Buffer/Base64；日期按数据库返回值展示/导出，不做应用层时区转换。
10. **元数据库治理**：WAL 模式、`busy_timeout`、单实例锁、版本化 migration、升级前备份；历史写入异步队列，退出前 flush。
11. **FTS5 子串/中文**：使用 `trigram` tokenizer（SQLite 3.34+ 内置）；不可用时对 `sql_text` 使用 `LIKE` 回退，并在设置中提示性能差异。
12. **阻塞隔离**：better-sqlite3 与导出任务运行于 Worker Thread；主进程只做调度与 IPC，避免大结果集/大文件导出冻结界面。
13. **MySQL 系连接与认证**：MySQL / Percona / MariaDB 在连接创建时作为独立类型；MySQL/Percona 使用 mysql2，MariaDB 使用 `mariadb` 驱动以覆盖 `ed25519` 等认证插件；驱动、认证插件与默认参数分别维护。
14. **时区**：显示与导出以数据库返回值为准，不做应用层转换；有时区类型保留原始偏移，无时区类型不补时区；不强制修改数据库会话时区。

#### A.5 已否决方案（决策记录）

| 方案 | 否决原因 |
|---|---|
| Tauri + Rust | 性能与体积最优，但 MSSQL 无成熟纯 Rust 驱动（tiberius 年轻），SQL 认证路径也缺乏端到端验证，风险不可接受 |

#### A.7 测试与质量基线

- 单元测试：方言 DDL 生成器快照测试（同输入 → SQLite/MySQL 系/MSSQL expected）、历史去重/淘汰逻辑、分页 SQL 生成、MOD-08 作业脚本生成（ALTER 骨架快照 + 命令引号转义）；
- E2E（Playwright for Electron）：连接 → 执行 → 历史搜索复用的完整主路径；
- 集成测试：docker-compose 起 MySQL 5.7/8.0/8.4、Percona 8.0/8.4、MariaDB 10.3/10.6/11.x、MSSQL 2017/2019/2022，验证连接与认证、分页、事务提交、DDL 执行；
- 性能基线：CI 记录启动耗时、历史搜索耗时、对象树加载耗时，作为回归门槛。
- 分句器边界：字符串/注释/`DELIMITER`/`GO` 独占行/多语句部分失败。
- 网格事务：乐观锁冲突、整批回滚、排除冲突行后提交、主键编辑拦截。
- SQLite 重建表：索引/触发器/视图依赖、外键 PRAGMA、失败回滚、`WITHOUT ROWID`。
- 历史搜索：中文、任意子串、10,000/50,000 条性能与 LIKE 回退。
- 类型映射：`BIGINT`/`DECIMAL` 精度、NULL 与空串、日期时区、二进制导出。
- 元数据库 migration：版本升级、备份、失败回滚、单实例锁。
- MOD-08：`step_id=0` 作业级结果、共享计划告警、`@step_id` 快照、命令引号转义。
- MOD-08 生命周期：启动/停止/启用/禁用、禁用作业启动拦截、重复点击防抖、多服务器按钮禁用、权限失败透传、`agent-control` 历史记录。

### B. 术语表

| 术语 | 含义 |
|---|---|
| DDL | Data Definition Language，建表/改表等结构定义语句 |
| SQL Server Agent | MSSQL 自带的作业调度服务（Job / Step / Schedule / Operators）；DBCraft v1.0 支持 Jobs 的监控、脚本化编辑与启停/启用/禁用（MOD-08） |
| Job 脚本化编辑 | 右键「编辑」生成包含 sp_update_job / sp_update_jobstep 等的 ALTER 风格脚本，在编辑器中打开供用户修改后执行 |
| 方言 | 各数据库的 SQL 语法差异（MySQL 系 vs MSSQL vs SQLite） |
| 预览弹窗 | UI 操作生成的 DDL 确认窗口，可编辑后执行 |
| 安全提交 | 数据编辑先进入待提交状态，由用户显式提交的事务模式 |
| 乐观锁 | 通过主键 + 原值比较（或 `rowversion`）检测并发修改，避免丢失更新 |
| FTS5 | SQLite 的全文搜索虚拟表；本项目用 `trigram` 分词支持子串与中文 |
| 分句器 | 按 `;`/`GO`/`DELIMITER` 将脚本切分为可执行语句的组件，需忽略字符串/注释内分隔符 |
| 行虚拟化 | 仅渲染可视区域行，支持大结果集流畅滚动（RevoGrid 内置） |
| 三段式表名 | MSSQL 的 `数据库.Schema.对象` 限定名 |
| 时区 | 显示与导出以数据库返回值为准；有时区类型保留偏移，无时区类型不补时区 |
| 作业生命周期控制 | 启动/停止/启用/禁用，直接调用 `sp_start_job` / `sp_stop_job` / `sp_update_job @enabled`，不修改作业配置 |
