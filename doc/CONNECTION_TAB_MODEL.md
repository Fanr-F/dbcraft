## 0. 先看结论

1. **当前没有「服务器」对象**。服务器信息（host/port/instance、认证、默认库、SSL、环境标签）全部塞在一个「保存连接」里；同一台服务器上的不同库、不同账号、Agent，只能靠多个保存连接或手工切库。
2. **一个 SQL 标签就是一个 session、一个物理连接**。同一保存连接开 3 个标签 = 3 条物理连接；关闭标签 = 关闭该连接；没有连接池。
3. **对象树是「当前标签的附庸」**：只有当前活动标签所属连接、且会话 ready 时才渲染对象；展开另一个连接会先切换/新建标签，不能同时浏览两台服务器。
4. **多库是隐式的**：每个标签有自己的当前库（`currentDatabaseByTab`），但标签标题不显示连接/库，状态栏也不显示当前库；切换标签后用户很难判断「这条 SQL 会在哪个库执行」。
5. **重连会丢库上下文**：SQLite 超时/断线后点「重连」，只重开连接，不恢复当前库；查询标签可能回到连接默认库执行。这是一个正确性风险。
6. **连接删除/编辑会影响打开的标签**：删除连接会把相关标签的 SQL 重置为 `SELECT 1;` 并清空结果；编辑连接会无提示地重连所有绑定标签。
7. **缺少标签管理与会话管理**：没有标签右键菜单（关闭其他/全部/复制/重命名/固定）、没有运行中/未保存/事务状态标记、没有活动会话列表、没有事务状态显示。

## 1. 当前模型（代码事实）

### 1.1 概念与落点

| 概念 | 当前实现 | 证据 |
|---|---|---|
| 保存连接 | `ConnectionRecord` + `ConnectionInput`：类型、名称、分组、环境、host/port/instance、database、用户名、SSL、字符集 | `src/shared/ipc-contract.ts` |
| 服务器 | **没有实体**；host/port/instance 只是连接字段 | 同上 |
| 数据库 | 会话级 `USE`；`schema:databases` 列表、`schema:use-database` | `ConnectionManager`、各 `*Session` |
| 会话 | 主进程 `sessions: Map<sessionId, DatabaseSession>`；`sessionId` 就是标签 id | `src/main/services/ConnectionManager.ts` |
| 标签 | `QueryTab`：SQL、connectionId、table/tableDesign/agentJob 等；标题多为「查询 N」 | `src/renderer/src/types.ts` |
| 当前库 | 渲染层 `currentDatabaseByTab`；对象树切换库时写入 | `App.tsx` |
| 连接状态 | 按保存连接聚合所有标签的会话状态 | `App.tsx` 的 `connectionStates` |
| 对象树 | 只渲染「当前活动连接 + 已展开 + session ready」的连接 | `Sidebar.tsx` |
| 断开连接 | 关闭该连接所有标签的 session；标签和 SQL 保留；下次执行重连 | `disconnectConnection` |
| 删除连接 | 解除绑定，相关标签 SQL 重置为 `SELECT 1;`、结果/待提交清空 | `deleteSavedConnection` |
| 编辑连接 | 保存后关闭并重开所有绑定标签的 session | `saveConnection` |
| 关闭最后标签 | 自动新建一个绑定同一连接的查询标签 | `closeTab` |
| 草稿恢复 | 只恢复 SQL 标签的 id/title/sql/connectionId/filePath，不恢复会话、库、结果、表数据/Agent 标签 | `DRAFT_STORAGE_KEY` |

### 1.2 关系图（当前）

```text
保存连接（配置）
  └─ SQL 标签 A ── sessionId=tabA ── 物理连接 ── 当前库 A
  └─ SQL 标签 B ── sessionId=tabB ── 物理连接 ── 当前库 B
  └─ 表数据标签 C ─ sessionId=tabC ── 物理连接 ── 表所属库 C

对象树 = 当前活动标签所属连接 + 当前库
服务器 = 没有独立节点
```

### 1.3 当前行为的隐性后果

- 同一保存连接开 N 个标签 → 服务器上 N 条连接；没有「连接预算/会话数」提示。
- 两个标签切到不同库后，标题都只显示「查询 N」；用户只能靠记忆或状态栏（状态栏也没有库名）。
- SQLite 超时后重连，当前库丢失；查询标签不会自动 `USE` 回原库。
- 删除连接会破坏标签里的 SQL 和结果；没有「保留 SQL、仅解除绑定」的选择。
- 编辑连接会立即重连所有标签；如果正在跑查询，行为不可控。
- 展开非活动连接会切换活动标签；不能像 SSMS/DataGrip 那样左侧同时浏览多个服务器。
- 一连接一会话的架构下，多标签对同一 SQLite 文件可能触发写锁；没有可见的会话/锁提示。

## 2. 术语建议（先把词定下来）

| 术语 | 建议定义 | 与当前实现的关系 |
|---|---|---|
| 服务器 Server | 一个数据库服务实例：类型 + host + port/instance；SQLite 是文件路径 | 需要新增概念；当前混在保存连接里 |
| 连接配置 Connection Profile | 服务器 + 认证 + 默认库 + SSL/字符集/环境/名称/分组 | 当前「保存连接」≈ 连接配置 |
| 会话 Session | 一条活着的物理连接；有当前库、事务状态、只读、版本 | 当前一个标签一个 session |
| 标签 Tab | UI 文档：SQL/表数据/表设计/作业详情；绑定连接配置，可拥有 session | 当前 `QueryTab` |
| 库上下文 Database Context | 会话当前 `USE` 的库；每个标签独立 | 当前 `currentDatabaseByTab`，但不可见 |
| 工作区 Workspace | 一组连接配置 + 标签布局 + 默认库 | 当前没有 |

> 建议在 UI 中统一叫法：左侧「服务器/连接」，中间「标签」，状态栏「会话」。不要把「保存连接」和「已打开的会话」都叫「连接」。

## 4. 推荐模型

### 4.1 目标关系图

```text
Server（类型 + host/port/instance；SQLite = 文件路径）
├─ Connection Profiles（认证/默认库/SSL/环境/显示名）
│    └─ Sessions（每条 SQL/表数据/DDL/Agent 标签默认一条）
│         └─ Database Context（当前 USE 的库）
├─ Databases
│    └─ Schemas → Tables / Views / Procedures / Triggers / Indexes
└─ SQL Server Agent（仅 MSSQL，服务器级）
```

### 4.2 关键规则

1. **服务器是身份，连接配置是凭据与默认值**。同一服务器可以有多个连接配置（不同账号/默认库/环境），但服务器节点只出现一次。
2. **保存连接是类，session 是对象，tab 与 session 强绑定**：一个 tab 对应一个 session；关闭 tab 关闭 session；不把 tab 改绑到另一个 session。SQL/表数据/表设计/Agent 标签默认各自拥有 session。
3. **库上下文属于 session**，但必须在标签标题和状态栏可见；执行按钮旁提供数据库下拉；新标签默认继承当前标签的库（同一连接配置）。
4. **交互入口分离**：双击保存连接 → 打开左侧对象树（browse session），不创建查询 tab；右击保存连接 →「查询」→ 创建 tab + 强绑定 session。完整服务器浏览器（多服务器同时展开）v1.x。
5. **断开/重连分层**：编辑保存只关闭该连接的 browse session，不关闭 tab session；显式「断开连接」可以关闭 browse + 该配置的 tab session（需二次确认）；重连恢复每个标签的库上下文。
6. **删除连接配置不销毁 session**：已有 tab session 保留运行、SQL/结果保留，标记「连接已删除」，由用户自行关闭；不强制关闭、不重置为 `SELECT 1;`；关闭后不可重连。
7. **编辑连接配置**：只更新配置，不重连、不关闭、不改写已有 tab session；关闭左侧树；用户双击连接重新连接 browse session；现有 tab 保留旧会话，新 tab/后续重连使用新配置。
8. **事务状态可见**：状态栏/事务面板显示当前标签的显式事务；网格未提交修改单独显示；关闭有事务的标签要提示。
9. **不做连接池**：继续「一个标签一个物理连接」；但必须显示会话数，并在连接数异常时提醒。
10. **不自动共享密码**：同一服务器的多个连接配置各自保存凭据；后续可做「复用服务器凭据」的显式选项。
11. **执行旁数据库下拉**：多数据库服务器在「执行」按钮旁提供数据库下拉；切换只影响当前 tab 的 session。

### 4.3 管理界面建议

| 界面 | 职责 | 建议优先级 |
|---|---|---|
| 服务器浏览器（左侧） | 服务器 → 数据库 → schema/对象；Agent 挂在服务器；显示活动会话数 | **v1.x**（Q26 B；v1.0 服务器实体先在数据模型/连接管理） |
| 连接管理器（弹窗/面板） | 服务器 + 连接配置；测试、复制、删除、导入/导出；默认库、环境、只读、凭据 | **v1.0**（Q21 A） |
| 标签管理器（标签栏） | 标题带连接/库；右键关闭系列/复制/重命名；未保存/运行中/事务标记 | **v1.0**（Q22 A + Q23 A） |
| 会话管理器（面板） | 活动会话列表：服务器、库、用户、运行状态、事务、开始时间；取消/断开/重连 | v1.x（v1.0 只做状态栏会话数 + 连接级重连，Q24 B） |
| 状态栏 | 服务器、当前库、会话短 id、事务状态、活动会话数 | **v1.0**（Q22 A + Q24 B + Q25 B） |
| 工作区（菜单） | 保存/切换连接+标签集合 | v1.x |

## 5. 建议的 v1.0 / v1.x 边界

### 5.1 v1.0 必做（Q21～Q26 决策后）

- **服务器实体（Q21 A）**：数据模型改为「服务器 → 连接配置 → 会话」；连接管理器按服务器分组，支持同一服务器多个配置（不同账号/默认库/环境）。
- **标签标题（Q22 A）**：连接名 + 当前库 + 查询序号；表数据/DDL/Agent 标签统一格式。
- **数据库下拉（Q22 A）**：位于「执行」按钮旁；每个非 SQLite 标签切换即对该标签 session `USE`；SQLite 显示 `main` 或隐藏；切换失败保持原库。
- **标签右键菜单（Q23 A）**：关闭、关闭其他、关闭右侧、全部关闭、复制标签、重命名；运行中/失败标签可带取消/重连。
- **标签状态标记**：未保存、运行中、失败、事务中。
- **状态栏（Q24 B + Q25 B）**：服务器/连接名、当前库、活动会话数、事务状态；连接级重连/断开。
- **事务面板（Q25 B）**：每个 SQL 标签显示事务状态，提供开始/提交/回滚；关闭有事务标签时提示；与网格未提交修改分开。
- **重连恢复当前库**：SQLite 超时/断线重连后回到原库，不落到连接默认库。
- **独立 browse session（Q27）**：双击保存连接打开左侧树（browse session），不创建查询 tab；右击 →「查询」创建 tab + 强绑定 session。
- **编辑/删除连接解耦（Q27）**：编辑保存只更新配置，不重连/不改写已有 tab session；关闭左侧树，双击连接重新连接；已有 tab 保留旧 session，新 tab/重连使用新配置。删除连接时已有 tab session 保留运行、SQL/结果保留，标记「连接已删除」，由用户自行关闭；不强制关闭/不重置；关闭后不可重连。

### 5.2 v1.x

- **服务器浏览器（Q26 B）**：左侧同时展开多个服务器/数据库；服务器 → 数据库 → schema/对象；Agent 挂在服务器层。
- 完整会话管理器（列表、取消、断开、重连、事务详情）。
- 工作区/项目、标签持久化、多窗口/拖出标签、分屏。
- 连接池/会话复用（如果未来推翻一标签一连接模型）。
- 标签固定/最近关闭/拖拽排序/中键关闭等增强交互。
- 连接配置凭据复用、服务器级健康检查。

### 5.3 不建议做

- 在 v1.0 引入连接池或按保存连接复用 session（会破坏现有「一标签一物理连接」隔离和 MSSQL 单请求模型）。
- 自动把同服务器连接合并成一个物理连接（用户可能用不同账号/环境）。
- 删除连接时静默清空标签内容。
- 在有运行中查询/未提交修改时无提示重连。

## 6. 验收标准（建议）

- AC: Given 同一连接打开两个标签并分别切到 `db_a`、`db_b`，When 切换标签，Then 标签标题/状态栏分别显示 `db_a`、`db_b`，数据库下拉显示对应库，执行 SQL 使用对应库。
- AC: Given 非 SQLite 标签，When 在数据库下拉选择另一个库，Then 该标签会话执行 `USE`，标题/状态栏更新；失败时保持原库并提示。
- AC: Given SQLite 会话超时后重连，When 重连成功，Then 标签恢复到超时前的当前库，不落到连接默认库。
- AC: Given 一个保存连接被两个 tab 使用，When 编辑该连接并保存，Then 两个 tab 不被重连/关闭/改写，SQL 与结果保留；左侧该连接的对象树关闭，双击连接后才重新建立 browse session。
- AC: Given 编辑保存后新建 tab，When 右击连接 →「查询」，Then 新 tab 使用新配置创建新 session；旧 tab 仍保持原 session，直到用户主动重连/关闭。
- AC: Given 双击保存连接，When 连接成功，Then 左侧对象树打开，不创建查询 tab；右击 →「查询」才创建 tab + session。
- AC: Given 对象树已展开，When 编辑连接保存导致树关闭，Then tab 的查询 session 不受影响（browse session 与 tab session 分离）。
- AC: Given 一个连接有 3 个打开的 tab，When 删除该连接，Then 3 个 tab 的 session/SQL/结果保留并标记「连接已删除」，不自动关闭或重置；用户手动关闭 tab 后不可重连。
- AC: Given 左侧有两个连接，When 展开非活动连接，Then 只展开对象树，不切换当前标签（v1.x 服务器浏览器）。
- AC: Given 同一连接打开 5 个标签，When 查看状态栏/连接节点，Then 显示 5 个活动会话。
- AC: Given 当前标签执行 `BEGIN`，When 查看事务面板/状态栏，Then 显示事务中；可提交/回滚；关闭标签时提示未提交事务。
- AC: Given 后台标签查询运行中，When 右键该标签，Then 可看到运行状态并取消查询。
- AC: Given 标签过多，When 右键当前标签选择「关闭其他」，Then 其他标签的会话被关闭，当前标签会话保留。
- AC: Given 同一服务器有两个连接配置（不同默认库/账号），When 打开连接管理器，Then 两者归在同一服务器下且可分别测试/编辑（Q21 A）。

| Q28 | 多窗口/工作区 | A. v1.0；B. v1.x | **已定 B** |

### Q27 的「编辑连接」指什么

- 指右键左侧连接列表里的**保存连接配置**（名称、分组、环境、host/port/instance、默认库、用户名/密码、SSL、字符集），不是编辑某个已打开 tab。
- **类/对象关系**：保存连接是配置（类），session 是运行时对象；一个 tab 与一个 session 强绑定。
- **已定规则**：编辑保存只更新配置，不重连/不关闭/不改写已有 tab session；关闭该连接所在的左侧树；用户双击连接重新连接后，才建立 browse session。
- 已有 tab 保留旧 session；新建 tab（右击 →「查询」）或后续重连使用新配置。
- 删除连接：关闭左侧树；已有 tab session 保留运行、SQL/结果保留，标记「连接已删除」，由用户自行关闭；不强制关闭、不重置；关闭后不可重连。
- 当前实现与上述规则不一致：保存编辑会静默重连所有绑定标签；删除连接会把标签 SQL 重置。实现时必须改。
- 为满足「关闭树但不影响 tab」，对象树需要独立的 browse session，不能继续完全依赖当前 tab 的查询 session。
