## 0. 结论（先看这 6 条）

1. **可追溯的原始需求只有 4 项核心 + 1 项追加 + 5 种数据库支持**：方言感知补全、查询历史、UI DDL、UI 表数据增删改；后来追加 MSSQL Agent Jobs；连接管理、结果导出、设置是支撑能力。
2. **PRD 实际展开成了 8 个模块、上百个可验收点**。其中相当一部分是文档自己长出来的：完整表设计器、索引/约束/CHECK、SQLite 重建表、FTS5、流式导出、无障碍、i18n、遥测、Monaco/Ant Design 等；多库对象树是你后来追加过的，单独按 L0/L1 处理。
3. **这些隐藏需求里，有的已经做了**（历史 FTS5、SQLite 重建、Agent 脚本化编辑、连接导入导出、Excel 导出、列/别名/库/Schema 补全、编辑器多语句/多结果页签），**有的没做**（流式导出、BLOB 编辑器、无障碍、性能基线）。
4. **真正影响「能不能用」的欠账**集中在：DDL 设计器完整度、网格编辑细节、导出上限/流式、Agent 剩余项、打包与真机验收，而不是 PRD 里的全部 P1。
5. **文档最大的问题不是功能少，而是层次混了**：PRD 把「建议」「技术选型」「P1」「v1.x」「非功能」都写进了 P0 语境；`PROJECT_STATUS` 又用完成度百分比把这些混在一起，看起来永远做不完。
6. **建议把需求切成三层**：v1.0 基线（只保留核心闭环）、v1.x 候选（明确延后）、技术/非功能附录（不作为功能验收）。PRD 不再承载实现选型。

### 2.1 R1 补全的真实差距

已有：

- 通用 SQL 关键字；
- 当前连接当前库的表/视图名；
- `Ctrl+Space` 手动触发；
- 前缀优先、包含匹配、键盘选择、Esc 关闭。

缺：

- 列名、表别名、`别名.`、`表名.`、库/schema、函数；
- `.` / 空格自动触发；
- 大小写跟随输入；
- 按数据库版本过滤（MySQL 5.7 不提示 CTE 等）；
- schema 缓存与懒加载；
- 错误波浪线、解析失败降级；
- 当前光标语句执行（目前只支持选区或全文）。

> 结论：原审计时「方言感知补全」只完成「关键字 + 表名」；W-20261109-19/20/21 已补齐列/别名/函数/库/Schema/多段限定名、大小写跟随与自动触发。剩余主要是版本感知、SQLite ATTACH 库内对象、MySQL 跨库列与解析失败降级。

## 6. 建议的 v1.0 需求基线

> 目标：v1.0 只承诺「连接 → 写 SQL → 执行 → 看结果 → 查历史 → 改结构 → 改数据 → 管 Agent」的闭环，不再把 v1.x 能力写进 P0 验收。

### 6.1 建议保留为 v1.0 必须

- 五类数据库连接：测试、打开/关闭、编辑/复制/删除、分组/搜索、最近使用、生产危险语句确认、SQLite 只读降级。
- SQL 编辑器：多标签、每标签独立会话、选中/光标语句执行、取消/超时、高亮、行号、括号匹配、格式化、**完整补全**（关键字/函数/库/Schema/表/列/别名/限定名/版本感知/自动触发）、SQL 文件打开/保存、30 秒草稿恢复。
- 查询历史：自动记录成功/失败/取消、FTS5 搜索、去重、脱敏、过滤、再次执行、详情、删除/清空、JSON 导出。
- UI DDL 主路径：新建表、编辑列（加/删/改/重命名）、重命名/删除表、新建/删除视图、普通/唯一索引、删除确认、SQLite 重建表（保留显式索引）、DDL 写历史。
- 表数据主路径：分页、单列排序、单列包含过滤（可扩到最多 3 条 AND）、单元格编辑、右键设为 NULL、新增行、删除单行、多行粘贴、撤销、单事务提交、乐观锁、无主键表只读。
- 结果与导出：网格展示、NULL/数字/日期样式、复制列名/单元格、单元格查看器、CSV/JSON/SQL/Excel、当前结果集导出、**多结果集/消息面板**、结果集「不限制」档位。
- 设置：主题、字号、结果上限、历史保留/去重/脱敏、查询/连接超时、诊断日志、元数据库备份/恢复、重置。
- MSSQL Agent：树入口、搜索/刷新、启停/启用/禁用、详情（步骤/计划/最近 100/500 历史）、脚本生成、共享计划警告、多服务器只读、`agent-control` 历史。
- 发布门槛：`typecheck` + 现有纯逻辑测试 + `build` + `smoke` + `e2e:sqlite` + 一轮真实 Electron 手工验收 + 打包验证。

### 6.2 建议降级到 v1.x

- 通配符展开、错误波浪线、当前行高亮、代码折叠、>1MB SQL 保护。
- 参数化执行；SQL 文件新建/另存为/最近文件/拖入（v1.0 只保留打开/保存）。
- DDL 设计器的索引/外键/CHECK/选项页签、CHECK 编辑、外键编辑、列序调整、可编辑预览、维护锁/进度/取消、SQLite 依赖对象保留、MSSQL 默认值/computed/rowversion。
- 类型化单元格编辑器、多列排序、「留空使用默认值」与显式 NULL 的完整区分、`IDENTITY_INSERT`、BLOB hex、多行删除、自动提交、冲突预检/跳过、`rowversion`、SQLite `rowid`。
- 流式导出/进度/取消、>1 万行、导出选项、选中区域/全部结果集导出、导出敏感提示。
- Agent 30 秒刷新、运行中状态、>1000 分页、右键菜单完整化。
- 跟随系统主题、i18n、字体族/Tab/关键字大小写、补全开关、网格偏好、数据目录迁移、启动恢复会话、快捷键自定义、本地统计清空/导出。
- 无障碍、性能基线、高 DPI、macOS/Linux、集成认证、SSH、证书级 SSL、SQLite 加密。

### 6.3 建议删除或移出需求文档

- 连接池表述（与「一标签一物理连接」冲突）。
- 网格提交使用独立连接/独立事务（同上）。
- 多语句/多结果集与单语句主查询的冲突表述（保留一种）。
- Monaco / Ant Design / Zustand / TanStack Query / SheetJS / `node-sql-parser` / `sql-formatter` / Vitest / docker-compose 作为「需求」的写法（移到技术附录或删除）。
- 遥测、NPS、激活率作为发布验收依赖（保留为内部目标）。
- 「不限制」结果集上限（如果决定不做）。
- 主密码回退方案（如果决定保留「加密不可用就不保存密码」）。

### 6.4 PRD 没写、但必须补的「反向缺口」

- 真实 Electron 手工验收清单与记录（当前大量 UI 只做过 E2E/代码走查）。
- 打包、签名、安装包验证（`pack` / `dist` 尚未验证）。
- MySQL / Percona / MariaDB 真实实例回归（当前只有 SQLite E2E 与 MSSQL 真机）。
- MSSQL 非默认命名实例、动态端口、Agent 权限不足/Agent XPs 禁用的真机回归。
- 文档漂移治理：每次改动同步 PRD/STATUS/README，避免再出现 C20/C21 这类过期描述。
- 测试门禁：现有 21 组纯逻辑测试 + SQLite E2E 必须全绿；CI 是否搭建单独立项。
